webskel-ui-engineering

MVM Contract

HTML and CSS resources own the View, services and authoritative domain state own the Model, and the presenter is the view-facing model responsible for lifecycle, actions, invalidation, child coordination, and safe state projection. WebSkel is the primary UI architecture, not a loader around a parallel manual DOM application.

Framework Capabilities

Ordinary clicks use data-local-action. Presenters use lifecycle hooks, invalidate, presenter readiness, registered child components, declared dependencies, and semantic events. Stable structure remains in HTML resources, repeated structure uses inert templates, and transient state updates preserve child presenter identity.

Safe Projection And Reuse

Dynamic values are projected through safe DOM properties rather than JavaScript-generated markup. Reusable concepts become registered WebSkel components with stable inputs and semantic output events, while persistence and authorization remain with their host.

Review Boundary

The skill requires reviewers to justify every explicit listener, reject avoidable direct click handlers and dynamic markup, verify cleanup and accessibility, and run focused tests plus visual validation when a browser target is available.
